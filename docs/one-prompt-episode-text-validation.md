# 一句话短剧第一集：纯文本验证项目

## 目标

验证 Alex 能否从一份固定原故事和一句导演令出发，自动形成连续剧规划、第一集正式文案与可生产分镜，同时严格停止在媒体制作之前。

本轮不验证最终画质，而验证以下生产主链是否成立：

```text
原故事 → 分集规划 → 第一集正式剧本 → 第一集分镜
```

## 固定输入

- 项目：`《桃园结义》AI 连续短剧验证项目`
- 来源：《三国演义》第一回完整公版原文，从回目到“且听下文分解”
- 测试集：第一集《榜下相逢》
- 目标时长：120–140 秒
- 核心人物：刘备、关羽、张飞
- 场景上限：招兵榜街市、酒肆，共两个主要场景
- 本轮导演令：

> 将《三国演义》改编成写实国风连续短剧，规划完整故事并生成第一集《榜下相逢》的草稿文案和分镜，目标时长约两分钟。固定刘备、关羽、张飞的人物设定和声音设定；本轮只生成文字，不生成图片、音频、视频或其他媒体资产。

原故事必须使用可核对的完整原文，不得先改写成剧情梗概，也不得人工预拆成四章。当前固定来源为公开仓库 `hailiang-wang/Romance-of-the-Three-Kingdoms` 中按回存放的第一回文本；导入前校验回目、开篇、桃园誓词和章末边界。

## 本轮范围

必须生成：

1. 一份项目级连续剧改编规划。
2. 第一集标题、梗概、场次和集尾钩子。
3. 第一集正式生产剧本，包括动作、结构化对白和镜头计划。
4. 第一集文字分镜，包括镜号、时长、景别、机位、动作、对白、声音说明和首尾帧策略。

明确禁止生成：

- 人物、场景、道具参考图片。
- VoiceProfile 参考音或逐镜对白 WAV。
- 首帧、尾帧、镜头视频和成片。
- 任何会启动 Azure Image、Azure Speech、ComfyUI 或视频模型的任务。

## 验证路径

优先直接调用 V2 API，以便准确观察每一步的任务结果和资产副作用：

1. `POST /api/v2/projects`：创建独立验证项目。
2. `POST /api/v2/projects/{projectId}/sources`：将完整第一回保存为单一来源，不预拆集。
3. `POST /api/v2/projects/{projectId}/sources/{sourceId}/analysis`：分析真实原文的人物、地点、关系和剧情节点。
4. `POST /api/v2/projects/{projectId}/sources/{sourceId}/script-draft`：使用 `mode=rearranged`、`desiredEpisodeCount=4` 生成四集规划。
5. `POST /api/v2/projects/{projectId}/sources/{sourceId}/script-draft/episodes/1/production-script`：只生成第一集正式剧本。
6. `POST /api/v2/projects/{projectId}/production-episodes/{episodeId}/storyboard/generate`：生成文字分镜。
7. 查询项目资产与任务记录，确认没有创建图片、音频或视频资产。

## 分镜阶段的已知边界

当前分镜命令在保存文字分镜后会调用逐镜对白生成。为了避免本轮产生音频：

- 使用全新项目，不创建任何 VoiceProfile 或参考音。
- 不配置或调用任何媒体生成入口。
- 分镜后的对白生成应因缺少角色音色而失败，只留下警告，不应创建音频资产。
- 分镜完成后立即查询资产类型；一旦发现媒体资产，停止后续操作并记录失败。

长期应为分镜 API 增加明确的纯文本模式，例如 `generateDialogueAudio=false`，消除依赖失败来阻止媒体副作用的做法。

## 通过标准

- 原故事、分集规划、正式剧本和分镜四层可以追溯。
- 第一集只覆盖榜下相逢、酒肆遇关羽和共同举事，不提前完成桃园结义。
- 刘备、关羽、张飞的姓名、外形原则、性格和声音方向前后一致。
- 每句对白有明确说话人，单句原则上不超过 18 个汉字。
- 对白使用自然短剧口语，不照搬文言或书面叙述；每句只表达一个意图。
- 正式剧本为每句对白预留独立镜头，文字分镜每镜最多一个说话人的一句对白。
- 分镜默认使用 `direct-first-frame`；仅明确需要锁定连续性终点状态时使用 `first-last-continuous`。
- 总分镜时长在 120–140 秒之间。
- 前 5 秒有钩子，最后 10 秒有下一集钩子。
- 文案与分镜生成完成后，图片、音频和视频资产新增数均为零。
- 任一步失败时能够从该步骤继续，不重新创建项目和来源。

### 基线结论与发现

- 纯文本技术链路已经跑通，但产品质量验证未通过，不能作为目标方案。
- 输入是 356 字加工梗概并被人工预拆为四章，不是真实第一回原文；`source-chapters` 只做确定性章节映射，不能验证从原著形成改编方案的能力。
- 对白存在书面腔和古装翻译腔；一个镜头最多包含 5 句对白；21 镜中有 10 镜使用首尾帧，均偏离短剧生产目标。
- 正式剧本质量满足本轮验证，但 `script-package` 没有保存 `GenerationMetadataJson` 或 Agent/Skill/Tool 来源，具体模型调用不可审计。
- 固定人物形象和声音目前只是项目设置与分镜文本约束；由于本轮禁止媒体生成，尚未验证跨镜头图片一致性、实际 VoiceProfile 一致性和最终混音。
- 分镜 API 仍会隐式尝试逐镜对白。本次因项目没有 VoiceProfile 而没有创建音频，但产品上仍应增加明确的纯文本开关。
- 首次本地 HTTP 调试受代理和终端编码干扰，留下一个未继续使用的空项目 `6498e2ec-03fe-4683-9a41-0a9b9640cf20`；未擅自删除。
