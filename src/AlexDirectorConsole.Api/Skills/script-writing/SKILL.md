# 剧本创作

## When to Use

用于从零创作剧本，或对项目中的已有剧本进行重写、改编、扩写、缩写、润色、节奏调整和目标时长改稿。输出必须成为项目中的 `script` 资源或已有剧本的新版本；只在聊天中展示正文不算完成。

剧本拆解、人物/场景/道具提取使用 `script-breakdown`；分镜和 shot list 使用 `storyboard-design`，不要用本技能替代。

## Required Inputs

- 从导演令提取题材、目标、受众、时长、风格、必须保留内容和禁止事项。
- 改写任务优先使用界面当前剧本。当前未选择资源时，先调用 `list_project_resources` 查找 `script`；目标唯一或可由名称明确匹配时自主选择，不要求导演重复选择。
- 找到已有剧本后，必须调用 `read_project_resource_contents` 读取目标资产的完整正文，再开始改写。
- 只有存在多个无法根据名称、导演令或最近对话区分的候选剧本时，才询问一个必要问题。

## Procedure

### 改写已有剧本

1. 确定目标 `script` 资产 ID；未选择时通过项目资源工具自主定位。
2. 调用 `read_project_resource_contents` 读取完整正文，不依赖列表摘要或聊天中的截断片段。
3. 列出导演要求形成的内部改写约束：目标时长、叙事重点、结构、语气、保留信息和禁止改动。不要把内部推理写进成稿。
4. 编写完整 Markdown 剧本。必须是可独立阅读和制作的全稿，不能只给差异、提纲、片段或修改建议。
5. 调用 `update_project_resource`，传入目标资产 ID 和完整新正文，创建该逻辑资源的新版本并保留旧版本。
6. 根据工具返回值汇报剧本名称和新版本号；不要在最终回复中重复粘贴整篇剧本。

### 新写剧本

1. 根据导演令确定剧本名称；名称不明确时使用内容中最稳定的项目名或片名，不使用“新剧本”“未命名”等泛称。
2. 编写完整 Markdown 剧本，包含创作任务实际需要的标题、基本制作参数、场次正文和必要备注。
3. 调用 `write_script` 保存完整正文。若项目中已有完全同名剧本，工具会创建该逻辑资源的新版本。
4. 根据工具返回值汇报剧本名称和版本号；不要声称保存了工具未返回的资源。

## Writing Rules

- 尊重导演令优先级，不擅自改变明确的人物身份、核心卖点、事实、结局或禁用内容。
- 动笔前先判定片型。导演要求“产品介绍、产品演示、功能讲解、操作流程、解决方案介绍”时，默认采用产品优先结构；只有导演明确要求“故事、剧情、人物弧光、情节化、品牌故事”等叙事表达时，才采用故事优先结构。不得仅因任务需要写成剧本，就自动虚构主角、冲突、倒计时或戏剧反转。
- 改写不是摘要。除非导演明确要求删减，原稿中的关键叙事信息必须有可追踪的保留、合并或替代表达。
- 场次按可拍摄空间和时间组织；动作、对白、旁白、屏幕文字和声音应清楚区分。
- 台词必须服务人物、信息或节奏，避免所有角色使用同一种说明腔。
- 动笔前确定全片声音方案。产品介绍、功能讲解和解决方案介绍默认使用可直接配音的逐字旁白承载产品定义、目标用户、关键工作流和价值收束；不得因画面已有界面操作就把全片旁白省略。导演明确要求纯视觉或无旁白时除外。
- 出现人物沟通、确认、质疑、决策、交接或情绪反应时，必须写出带角色名的逐字对白，让对白完成真实沟通动作；不得只写“人物交流”“团队讨论”等画面说明。没有人物沟通需求的场次不必机械添加对白。
- 所有需要被说出的内容必须是可直接交给演员或 TTS 的完整文本。禁止用“无”“待定”“后续补充”“同上”“旁白介绍产品”“根据画面发挥”等占位。某场确实不需要某类声音时省略该小节，不要用占位文本充数。
- 剧本是逐字旁白与对白的唯一内容来源。所有措辞删改、压缩、扩写、角色归属和声音节奏问题都必须在 `script` 中解决并保存为新版本；不得把修词任务下放给分镜。
- 产品优先片必须尽快说明产品是什么、服务谁、解决什么问题，再按真实使用顺序展示能力、操作结果和最终价值。可以使用简短场景帮助理解，但场景只承载产品信息，不要求人物冲突、情节升级或线索回收，也不得让虚构情节压过产品本身。
- 故事优先片的主角必须有可观察的目标、时间压力或代价；至少出现一次阻碍升级、一次由人物选择或产品能力触发的局面逆转，并在结尾回收开头建立的问题或视觉线索。该规则不得用于导演明确要求的纯产品介绍、演示或讲解片。
- 信息揭示应形成因果链。产品优先片体现为“问题或输入 → 产品操作/能力 → 可见结果 → 下一步工作流”；故事优先片体现为“人物行动 → 新结果 → 下一步选择”。不得用彼此可互换的“操作一下、成功了”场次拼接全片。
- 每场至少改变一项可见状态，例如时间、任务完成度、人物关系、情绪、空间秩序或风险；删除该场不影响故事时，必须合并或重写。
- 旁白只补充画面无法自然表达的信息；关键转折优先由动作、界面反馈、声音变化和人物反应呈现。让台词带有意图与潜台词，不让人物互相朗读产品说明。
- 产品优先片开场应在导演指定时间内说明产品定位、目标受众和核心问题；未指定时优先在前 10–15 秒完成。中段按工作流展示产品，结尾用具体前后对比或结果收束。故事优先片则尽快出现异常、难题或未完成动作，中段承受压力测试，结尾回收开场问题。
- 导演指定目标时长时，按实际动作、对白、停顿和转场估算总时长，并在交稿前调整到范围内；不能只修改标题中的时长数字。中文逐字旁白与对白按不高于每秒 4 个汉字核算基础口播时间，角色名、章节标题和不发音的声音提示不计入字数；动作、停顿、提示音和转场必须另留时间。任一场的声音无法放入该场时长时，先在剧本中删改台词或调整场次时长，不得留给分镜自行压缩。
- 90–120 秒等短片优先保留一个清晰主线，每个场次承担明确叙事功能，避免无法在时限内执行的信息密度。
- 未经导演要求，不建立 shot、不生成图片、不拆解人物/场景/道具资源。

## Pitfalls

- 不因界面未选择资源就停止在“先给导演确认”的聊天输出；先自主发现目标并持久化。
- 不把 `read_project_resources` 返回的摘要当作完整原稿；改写前读取完整正文。
- 不调用 `write_script` 另建同名副本来逃避版本管理；已有目标使用 `update_project_resource`。
- 不覆盖 Blob 或旧版本；只使用写入工具创建不可变新版本。
- 不引用、读取或修改其他项目的资源 ID。
- 不在工具成功前说“已重写”“已保存”或“已更新”。

## Verification

- 工具返回的 Asset 类型为 `script`，项目为当前项目，名称与目标一致。
- 改写任务返回版本号大于原版本，且 `resourceId` 与原剧本一致。
- 新写任务已由 `write_script` 返回真实 Asset。
- 成稿覆盖导演明确要求；指定时长时，动作、对白和转场估算位于目标范围。
- 声音方案检查通过：所有计划被听见的旁白和对白都有逐字正文，不含占位；产品介绍片在产品定义、核心问题、关键工作流和价值收束处都有可听信息，除非导演明确要求无旁白；存在人物沟通动作的场次都有对应角色对白。不要机械要求每场同时出现对白和旁白。
- 逐场声音时长检查通过：去除角色标签和不发音提示后，中文口播不超过每秒 4 个汉字，并为该场动作、停顿、音效和转场保留实际时间。任何一场超载都必须在保存剧本前修订。
- 保存前先确认片型。产品优先片逐项检查：产品是什么；服务谁；解决什么问题；能力是否按真实工作流展示；每项能力是否有可见输入、操作或结果；结尾是否给出具体价值。不得因缺少主角、冲突、高潮或线索回收而拒绝写入。
- 故事优先片逐项检查：主角想完成什么；什么具体阻碍正在加剧；哪次行动改变了局面；高潮要求主角做出什么选择；结尾回收了什么。任一项无法从成稿中的可见动作或可听台词指出时，不得写入。
- 逐场删除测试通过：产品优先片每场都完成产品定义、问题说明、能力演示、工作流推进或价值收束；故事优先片每场都推进任务、升级阻碍、揭示能力或完成情绪转变。
- 最终回复只简要报告实际保存结果和关键改写方向，不重复整篇正文。
