# 剧本创作

## When to Use

用于从零创作剧本，或对项目中的已有剧本进行重写、改编、扩写、缩写、润色、节奏调整和目标时长改稿。输出必须成为项目中的 `script` 资源或已有剧本的新版本；只在聊天中展示正文不算完成。

剧本拆解、人物/场景/道具提取使用 `script-breakdown`；分镜和 shot list 使用 `storyboard-design`，不要用本技能替代。

## Required Inputs

- 从导演令提取题材、目标、受众、时长、风格、必须保留内容和禁止事项。
- 改写任务优先使用界面当前剧本。当前未选择资源时，先调用 `list_project_resources` 查找 `script`；目标唯一或可由名称明确匹配时自主选择，不要求导演重复选择。
- 找到已有剧本后，必须调用 `read_project_resource_contents` 读取目标资产的完整正文，再开始改写。
- 只有存在多个无法根据名称、导演令或最近对话区分的候选剧本时，才询问一个必要问题。

## Procedure

### 改写已有剧本

1. 确定目标 `script` 资产 ID；未选择时通过项目资源工具自主定位。
2. 调用 `read_project_resource_contents` 读取完整正文，不依赖列表摘要或聊天中的截断片段。
3. 列出导演要求形成的内部改写约束：目标时长、叙事重点、结构、语气、保留信息和禁止改动。不要把内部推理写进成稿。
4. 编写完整 Markdown 剧本。必须是可独立阅读和制作的全稿，不能只给差异、提纲、片段或修改建议。
5. 调用 `update_project_resource`，传入目标资产 ID 和完整新正文，创建该逻辑资源的新版本并保留旧版本。
6. 根据工具返回值汇报剧本名称和新版本号；不要在最终回复中重复粘贴整篇剧本。

### 新写剧本

1. 根据导演令确定剧本名称；名称不明确时使用内容中最稳定的项目名或片名，不使用“新剧本”“未命名”等泛称。
2. 编写完整 Markdown 剧本，包含创作任务实际需要的标题、基本制作参数、场次正文和必要备注。
3. 调用 `write_script` 保存完整正文。若项目中已有完全同名剧本，工具会创建该逻辑资源的新版本。
4. 根据工具返回值汇报剧本名称和版本号；不要声称保存了工具未返回的资源。

## Writing Rules

- 尊重导演令优先级，不擅自改变明确的人物身份、核心卖点、事实、结局或禁用内容。
- 改写不是摘要。除非导演明确要求删减，原稿中的关键叙事信息必须有可追踪的保留、合并或替代表达。
- 场次按可拍摄空间和时间组织；动作、对白、旁白、屏幕文字和声音应清楚区分。
- 台词必须服务人物、信息或节奏，避免所有角色使用同一种说明腔。
- 产品片和宣传片必须把功能转化为可见操作、结果和使用情境，避免连续口号堆叠。
- 导演指定目标时长时，按实际动作、对白、停顿和转场估算总时长，并在交稿前调整到范围内；不能只修改标题中的时长数字。
- 90–120 秒等短片优先保留一个清晰主线，每个场次承担明确叙事功能，避免无法在时限内执行的信息密度。
- 未经导演要求，不建立 shot、不生成图片、不拆解人物/场景/道具资源。

## Pitfalls

- 不因界面未选择资源就停止在“先给导演确认”的聊天输出；先自主发现目标并持久化。
- 不把 `read_project_resources` 返回的摘要当作完整原稿；改写前读取完整正文。
- 不调用 `write_script` 另建同名副本来逃避版本管理；已有目标使用 `update_project_resource`。
- 不覆盖 Blob 或旧版本；只使用写入工具创建不可变新版本。
- 不引用、读取或修改其他项目的资源 ID。
- 不在工具成功前说“已重写”“已保存”或“已更新”。

## Verification

- 工具返回的 Asset 类型为 `script`，项目为当前项目，名称与目标一致。
- 改写任务返回版本号大于原版本，且 `resourceId` 与原剧本一致。
- 新写任务已由 `write_script` 返回真实 Asset。
- 成稿覆盖导演明确要求；指定时长时，动作、对白和转场估算位于目标范围。
- 最终回复只简要报告实际保存结果和关键改写方向，不重复整篇正文。
