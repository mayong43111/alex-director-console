# 分镜设计

## When to Use

用于把一集、一个场次或一段剧本拆成可执行的分镜稿、镜头表或粗分镜方案，也用于按导演明确指令清理旧分镜或旧 shot。新分镜输出必须基于剧本文本以及项目中最新的人物、场景和关键道具设定，不凭空补写剧情事实。

## Required Inputs

- 优先使用界面当前选中的剧本或文本资源。
- 当前未选择资源时，从导演令和最近对话确定集数、标题或场次名称，再调用 `read_project_resources` 读取对应剧本。
- 读取剧本后，提取其中出现的人物、场景和关键道具名称，并再次调用 `read_project_resources` 批量读取其最新设定稿。
- 只有无法从当前资源、导演令、最近对话和项目资源确定目标剧本时，才向导演询问一个必要问题。

## Procedure

导演要求删除、清理旧分镜或只保留指定版本时，执行清理流程：

1. 只要导演话语包含“删除、删掉、清理、移除、只保留”等处置含义，就先调用 `list_project_resources` 列出 `shot` 资源；用名称、镜号和导演指定的版本识别保留集合与删除集合。不能把导演的话直接当成已完成状态。
   - “V1 的都删除了”“旧版都删了”这类省略“把”字的口语，默认按立即删除命令处理。
   - 只有导演明确说“我已经删除、不用操作、只是告知”时才按状态说明处理，但仍须列出资源验证是否确实不存在。
   - 若最近一次任务是为当前剧本完整重做分镜且 `write_storyboard` 未成功，导演紧接着说“清理旧记录”“删掉旧分镜”等，现存的该剧本全部 shot 就是旧记录；直接批量删除并复查，不再询问保留哪一套。失败的写入没有产生可保留的新分镜。
   - 若完整新分镜已经成功写入，导演说“删除旧分镜”“清理旧记录”且未要求删除当前分镜，含多个版本的 shot 应调用 `purge_project_resource_versions`，保留每个逻辑镜头的最新版本并删除旧版本。不得调用 `delete_project_resource` 删除整条当前镜头，也不得把仅有 v1 的新场次（例如新增加的 S08、S09）视为旧记录。
2. 如果导演已经明确了保留版本，不再要求重复确认。若存在两个同名或无法区分的候选版本，只询问一个必要问题，不得猜测。
3. 待删除集合非空时，调用一次 `delete_project_resource`，将全部待删除 shot 的资源 ID 以逗号或换行分隔传入；不要逐个调用。集合为空时不得调用删除工具，也不得声称本轮执行过删除。
   - 仅清理历史版本时改用一次 `purge_project_resource_versions`，传入所有目标 shot 的当前资产 ID。工具会保留各逻辑资源最新版；返回 `deletedVersionCount=0` 的资源本来就没有旧版本，不是删除失败。
4. 再次调用 `list_project_resources`，确认保留集合仍存在、删除集合已消失。只有删除工具成功且复查通过，才汇报“已删除”；目标原本就不存在时，明确汇报“未找到匹配资源，本轮删除 0 项”。

导演要求新建设计或改写分镜时，执行设计流程：

1. 调用 `read_project_resources` 读取目标剧本完整正文。
2. 调用 `read_project_resources` 读取剧本涉及的人物、场景和关键道具最新设定；不存在的设定应在分镜稿中标记为待确认，不得自行补全。
3. 先逐场核对剧本中的逐字对白、旁白、动作、停顿和场次时长。分镜只能逐字承接剧本声音，不得删词、换词、合并台词、另写台词或改变角色归属。若按正常语速无法容纳，停止分镜写入并明确要求先用 `script-writing` 修订剧本；不得在分镜中替剧本压缩声音。
4. 按剧本场次顺序设计镜头。这里的“一个镜头”采用传统拍摄定义：摄影机从开机录制到停机的一条连续 take。拆镜依据是实际停机、换机位，或无法连续拍摄的时间/空间跳跃；动作开始、动作完成、信息揭示、人物反应、对白换人和界面状态变化本身都不是拆镜依据。同一机位和连续时空内可一次完成的动作链、对白与操作结果必须优先保留在同一镜号中。
5. 编写完整 Markdown 分镜稿，至少包含：
   - 项目与依据：集数、标题和导演令；不得列出人物、场景、道具或其他来源资源 ID/版本。
   - 视觉总则：画幅、视角、运动、色彩、光线、节奏和连续性原则。
   - 逐场分镜表：镜号、角色/主体、场景/时空、景别、机位/角度、画面与动作、台词/声音、镜头运动、预计时长、连续性/制作备注。角色和场景必须明确填写，不得只隐含在动作描述中。
   - 场次转场与节奏小结。
   - 待导演确认事项，只列真实缺口。
    - `write_storyboard` 只解析标准 Markdown 表格。每个逐场分镜表的首列标题必须精确为 `镜号`，下一行必须是标准分隔行，每个镜号必须位于独立数据行。使用以下格式，不得改为标题列表、编号列表、字段块或把 `镜号` 放到非首列：

       ```markdown
       ## S01 内景·工作室·深夜

      | 镜号 | 角色/主体 | 场景/时空 | 景别 | 机位/角度 | 画面与动作 | 台词/声音 | 镜头运动 | 预计时长 | 连续性/制作备注 |
      | --- | --- | --- | --- | --- | --- | --- | --- | --- | --- |
      | S01-01 | 导演、控制台 | 内景·工作室·深夜 | 全景 | 门侧略高机位 | 开机画面；连续动作；停机画面 | 导演：逐字台词；环境声 | 缓慢前推 | 5s | 连续性要求 |
       ```
6. 镜号使用稳定格式 `S场次号-镜头号`，例如 `S03-05`。每场从 `01` 开始，保持剧本顺序。
   - `Sxx` 必须对应来源剧本的实际场次编号：剧本第 1 场只能使用 `S01-*`，第 2 场只能使用 `S02-*`，依此类推。不得为了连续编号方便把多场剧本全部压进 `S01`，也不得跳过剧本场次。
7. 只有导演在当前指令或此前已确认的要求中明确指定总时长时，才设置目标总时长区间。不得根据题材、场数、剧本长度、行业惯例、成片类型或 Agent 自己的判断猜测、推荐或补设时长。导演明确给出区间时换算为整数秒，例如“1 分到 1 分半”传 `targetMinimumSeconds=60`、`targetMaximumSeconds=90`；导演只给单一目标时长时，以该值为中心使用不超过 ±5% 的区间。导演没有明确指定时，两者都传 `null`，表示总时长不受限制。
8. 写入前先在内部逐行提取“预计时长”的单一秒数并求和。每镜必须为 3–60 秒。导演指定了目标区间时，总和必须落在区间内；未指定时不得为了落入 Agent 自拟的总时长而压缩、扩写或重分配镜头，只按剧本中的动作、逐字声音、停顿和转场如实设计时长。
9. 调用 `write_storyboard`，传入清晰的分镜名称、Markdown 正文、来源剧本的 `scriptAssetId`；仅在导演明确指定时长时传入整数 `targetMinimumSeconds` 和 `targetMaximumSeconds`，否则两者都传 `null`。新建或完整改写全片时传 `replaceExistingShots=true`，工具会删除本稿未包含的旧镜头；只修改指定场次或镜头时传 `replaceExistingShots=false`，工具会保留其余镜头。两种模式都按“剧本 + 场号 + 镜头号”更新稳定逻辑镜头，重新生成同一镜头只新增版本。
   - `scriptAssetId` 可以是该逻辑剧本任一版本的资产 ID；工具会解析到最新版本。优先传最近读取结果中最新剧本版本的资产 ID，不要从旧对话复制过期版本 ID。
   - 工具失败时必须以异常原文为准定位原因。例如返回“来源剧本中不存在的场号”时，检查剧本版本与场次编号，不能改口称为 Markdown 格式问题；导演明确指定时长且返回时长越界时只调整时长。修正异常明确指出的问题后再重试。
   - 同一输入、同一参数不得原样重试。连续失败后仍有明确错误时继续针对该错误修正；只有错误信息为空或确实存在多个无法区分的外部事实时，才向导演提问。不得在可自行修复时以“如果你同意，我下一步排障”结束任务。
10. 仅根据工具返回结果汇报已创建的独立镜头数量、镜号、版本和 `totalDurationSeconds` 统计出的当前预计总时长。导演指定了目标时长时同时汇报目标区间；未指定时明确说明“本次未限制总时长”，不得补报 Agent 自拟目标。

## Storyboard Rules

- 一个 `shot` 等于一次开机到停机。只有实际切换机位/角度、重新开机，或出现无法在同一次连续拍摄中完成的时间与空间跳跃时，才必须另起镜号。
- 单条镜头只使用一个明确机位和一套可执行的摄影运动。不能在同一行中写“先拍甲特写，再切乙反应”等隐含剪辑；但同一机位内通过推拉、摇移、跟拍、连续变焦或焦点转移形成的景别与关注点变化仍属于同一镜头，不得误判为切镜。
- 不得按动作节拍机械拆镜。同一机位内的“输入指令 → 确认 → 界面生成结果”、人物连续操作与反应、完整一句旁白/对白及其对应画面，应写成一条连续镜头；不能因为动作完成、结果出现、信息揭示或说话人变化就另起镜号。
- 一条镜头可以同时拍到多个人物，但他们的动作必须处于同一连续时空、能由同一摄影机一次完成；人物数量不是合并镜头的理由。
- 按实际表演和摄影时间核对时长。5 秒镜头只能承载约 5 秒内可完整执行的单一动作或连续动作链，不得塞入多个独立叙事节拍、轮番反应或跨机位信息。
- 常规叙事镜头预计时长通常为 3–15 秒。少于 3 秒的闪切、插帧或黑场必须并入相邻镜头；同一机位需要承载完整动作链、对白或旁白时，可使用 16–60 秒的连续长镜头，不得为了压到 15 秒以内按动作或语句拆出伪切镜。
- 不把所有镜头机械设成 3–5 秒，也不把场次时长平均分给固定数量的镜头。镜头时长由该机位内完整表演、操作和声音的实际耗时决定；先按正常语速核算完整台词，再给动作与停顿留出时间。
- 每条“画面与动作”应明确开机时的起始画面、连续发生的动作、停机前的结束画面，供现场直接按条拍摄。
- 每个有人物可见且持续 3 秒以上的镜头，必须至少包含一个与剧本事实一致、在该景别和预览分辨率下清楚可辨的主体动作或连续动作链，例如转移视线后移动纸张、伸手操作设备、起身、转身或改变站位。呼吸、眨眼、细小眼神变化和不可辨的手指微动只能作为生命微动作，不能单独充当镜头的有效动作。
- 若剧本只规定人物“坐着不动”“站着不动”或“保持原位”，分镜设计应在不改变剧情事实的前提下，从现场行为中选择一个唯一、克制且可见的动作；不得机械写成“呼吸 + 眨眼”。如果没有任何可合理补充的可见动作，则缩短镜头、改为明确的摄影机/环境运动驱动镜头，或把真实缺口列为待导演确认，不得把弱动作镜头直接写入。
- 建立空间的大全景若以摄影机运动为主，仍需判断画内主体是否有可读变化；人物眨眼在大全景中不计为有效动作。纯黑场、明确静物镜头、后期版式镜头和导演明确要求的定格画面不受此条约束。
- 不改变剧本事件顺序、人物身份、逐字台词、旁白、声音归属和已确认设定。剧本中的声音文字必须原样出现在对应镜头；一段声音跨多个镜头时只能按原文顺序切分，不得增删改写。
- `台词/声音` 必须显式保留声音归属：旁白写作 `旁白：原文`，角色对白写作 `角色名：原文`；环境声、音乐、停顿和音效另行标注，不得让制作人员猜测说话者。
- 明确区分剧本写明、导演确认和分镜设计选择。
- 避免不可执行的抽象描述；画面、动作、机位和声音必须能被拍摄或绘制。
- 同一动作的轴线、视线、出入画方向、道具位置、光源方向和人物状态必须连续。
- 对对白场景优先建立空间关系，再进入中近景；越轴必须有可见的过渡依据。
- 时长应与动作和台词量匹配；不把所有镜头机械设置为相同时长。
- “预计时长”必须填写单一秒数，如 `3s`、`8s`、`15s`；不得填写 `3–5s`、`约十秒`、`待定`。分镜总时长等于全部镜头预计时长之和，不得另行估算或忽略转场镜头。
- 每个场次至少包含一个视觉变化点。产品介绍片可以是新输入进入、产品操作、界面状态改变、工作流推进或现实结果出现，不强制阻碍、反转、人物关系变化或线索回收；故事片则可使用这些戏剧变化。只重复“人物操作界面并成功”的镜头必须合并或改写。
- 镜头组合必须形成可读的因果节奏。产品介绍片采用“问题或输入 → 产品操作/能力 → 可见结果 → 下一步工作流”；故事片采用“目标或危险 → 行动 → 结果与反应 → 下一选择”。连续三个镜头若景别、运动、主体动作和信息状态均无显著变化，必须至少重写其中一个。
- 软件界面镜头必须同时交代操作前状态、一个可辨操作和操作后结果；界面录屏不可连续承担全部叙事，须穿插人物、环境、道具或现实后果，让软件能力改变画外世界。
- 每个镜号必须对应一个独立的文本 `shot` 资源，不能把整集或整场分镜只保存成一个文件。
- 修改、重生成或去重前先调用 `query_storyboard`。按 `scriptAssetId + sceneNumber + shotNumber` 定位，不按名称或创建时间猜测；需要检查素材 take 时使用 `includeTakes=true`。
- `shot` 是镜头设计，不是制作资源清单；不得写入“来源资源”章节，不得固化人物、场景、道具图片或设定稿 ID/版本。后续生成镜头画面时由对应技能动态查找项目中的最新资源。
- 文本镜头资源不调用图片生成工具。导演另行要求出分镜图时，再使用对应图像技能或工具。

## Pitfalls

- 不因界面未选择资源就立即要求导演重新提供内容；先查阅最近对话和项目资源。
- 不把“V1 的都删除了”误判为无需操作的状态澄清；默认按删除命令执行查询、删除和复查。
- 不依据导演口述或对话历史声称资源已删除；“已删除”必须有本轮删除工具结果和复查结果支撑。
- 导演明确要求清理旧分镜时，不得以“工具不支持删除”为由只做口头标记；使用 `delete_project_resource` 实际删除。
- 只能删除当前项目中由 `list_project_resources` 返回的资源；不得引用、发现或清理其他项目的资源 ID。
- 清理时不得删除导演指定保留的 shot，不得把不同分镜版本仅凭创建时间混为一组。
- 不只输出建议或示例，必须调用 `write_storyboard` 持久化完整稿件。
- 导演未指定总时长时，不得以“常规节奏”“合理时长”“行业惯例”或类似理由自行设定目标，也不得将 Agent 编写的剧本标题或制作参数当成导演的时长要求。
- 不忽略工具异常中的具体字段和值，不把明确校验错误泛化为“格式可能更严格”，也不在错误仍可自行修复时停止并请求导演批准排障。
- 不把人物设定、场景设定或道具设定中的推测当成剧本事实。
- 不创建工具未返回的资源，不声称已生成分镜图片。

## Verification

- 清理任务：记录删除工具实际返回数量，再次列出 shot，确认待删资源为零且保留版本完整；若初次查询即为零，报告本轮删除 0 项。
- 设计任务：确认 `write_storyboard` 返回的 `shotCount` 等于逐场分镜表中的镜头行数，并记录 `totalDurationSeconds` 供最终汇报；导演指定了目标时长时确认总时长位于返回的目标区间，未指定时确认两个目标字段均为 `null`。每个返回项必须是独立 `shot` 资源；检查最新剧本的所有场次均被覆盖、镜号无重复，并确认生成的 shot 不含“来源资源”章节或资源 ID 快照。逐镜复查 3 秒以上的人物镜头具有当前景别可辨的有效动作；只剩呼吸、眨眼或不可辨微动作的镜头必须在写入前改写。
